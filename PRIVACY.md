# EchoInk Agent — privacy and data

The complete disclosures for the EchoInk Agent plugin. A short summary is in the [README](README.md#privacy-at-a-glance). 中文版见 [PRIVACY_CN.md](PRIVACY_CN.md).

## Where data is stored

- **Local content:** Conversations, notes, knowledge, memory, diary content, and financial records are stored locally. The plugin does not upload your entire vault by default.

- **Model credentials:** Provider API keys and OpenAI Codex Beta sign-in credentials are saved in plugin settings for the current vault. Use trusted devices and vaults.

- **Desktop account storage:** On desktop, account sessions and device authorization are encrypted under **`~/.echoink/membership/`**, outside the vault. Operating-system secure storage protects the shared device authorization; Obsidian's secret storage protects each vault's account session separately. If secure storage is unavailable, persistent device authorization cannot complete, and existing credentials are preserved.

- **Mobile account storage:** On mobile, account sessions and authorization use the current vault's Obsidian secret storage, not ordinary plugin settings. Activation applies to each vault's client instance, so different vaults on the same device may occupy separate slots. Unlink unused instances in device management. If secure storage is unavailable, state is kept only for the current session.

- **Conversations and work records from other devices.** Share data with other devices is on by default on desktop, phone, and tablet. It writes device names and activity times, work projects and their progress, conversation titles and message text, and brief tool steps to `EchoInk/同步数据` in the current vault. The first pass mirrors conversations updated in the last 30 days. Later passes update a conversation when it produces a new result. Creating the mirror and opening received records require no EchoInk account. If you enable EchoInk Cloud Sync, these records are encrypted and transferred as described below. If you include this folder in Obsidian Sync or another tool, that service stores its copies under its own privacy and retention terms. Turning off mirroring stops future writes. Files already created stay in the vault and can still be transferred by a sync service you have enabled. On desktop, continuing a chat can create a new local conversation with the received messages. On mobile, the received text is first added to the draft. When you send it, the selected model service's policy applies.

## Features that connect to echoink.cn

- **Account and authorization:** EchoInk's account service at **https://echoink.cn** handles registration, sign-in, email verification, redemption, subscriptions, and device authorization. It receives the account information and authorization data required for those requests, including a generated device identity. An EchoInk account and an active entitlement are required for PRO plugins; ordinary chat and Knowledge do not require an EchoInk account.

- **Official PRO Skills:** Official PRO Skills download on demand from **https://echoink.cn**. Seven methodology Skills are delivered remotely; knowledge review retains its complete local basic version and uses a remote enhancement when PRO is valid. The catalog is public, including names, summaries and available comparison links. Content requires sign-in, unified PRO access and an activated device. Finance, English Diary, basic Obsidian operations, Quick Journal and to-do Skills remain bundled.

- **Skill requests and cache:** Skill downloads use the account service to send the login token, Skill ID, device ID, current signed lease, plugin version, platform and optional cached version. They send no notes or conversations. Versioned Markdown is cached in **`skill-cache/`** under the current Vault’s actual plugin data directory, following its configured directory and existing data-root selection, isolated by account, service URL and device. These are ordinary local files and can be copied. Every use requires a valid device lease and less than 7 days since the full content’s `issuedAt`. Cache reads and “not modified” responses never extend that period. Only temporary network failures permit fallback to a still-valid cache. Sign-out, expiry, device revocation or a known entitlement revocation stops access; a fully offline device cannot immediately learn of remote revocation. Each run fixes one content version; updates apply to a later run. Skill text grants no tools or permissions.

- **Expert catalogs and content:** The public catalog request sends the plugin version to echoink.cn so the server can return compatible experts. Content downloads require active PRO and device authorization. Requests include the expert ID, device ID, signed lease, plugin version, platform, and optional cached version; these download requests send no notes or conversations. Downloaded content is cached in `expert-cache/` under the current plugin directory. Before each run, a community expert needs an online check to confirm it is still listed.

- **Community expert submissions:** When you confirm a submission, echoink.cn receives the name, use case, summary, quote, tags, example questions, persona, attached vault Skill text, avatar choice or image, and the public name you approve. EchoInk stores the submission with your account for review. If accepted, public details and attribution appear in the catalog. People who hire the expert receive the persona and Skill text on their devices for use with their chosen model.

- **Expert hire statistics:** After a successful local hire, the plugin reports the expert ID with your signed-in session. EchoInk counts each account once per expert, across devices, vaults and repeat hires. The catalog shows the aggregate count.

- **Weather:** Weather is optional. Searching for a city sends the search text to echoink.cn. Once you select a city, EchoInk stores its ID and name in this vault's plugin settings and sends only the city ID to echoink.cn when the workbench opens and every 30 minutes while visible. Weather requests contain no login token or account data; EchoInk does not read device location or store weather history. Weather is a near-term estimate from MET Norway, not a local observation. Weather and city sources, licenses and adaptations remain visible in General settings.

- **Workbench check-in:** Workbench check-in is an online account action. Opening the Workbench while signed in queries your account's status for the local date. Only pulling the weather doll down or pressing Arrow Down submits a manual check-in, sending your account identity through the existing login token, local date, and time zone to **https://echoink.cn**. Check-ins are saved with your server account and cached only in memory by the plugin. There is no automatic check-in or upload of Agent usage days, notes, or conversation content.

- **Run records and reports:** From a session’s **…** menu, you can export its run records or voluntarily upload a problem report to **echoink.cn**. Reports include conversations, note excerpts read by the agent, tool and runtime logs, environment details, and errors, together with your description and optional contact information. Signed-in submissions are linked to your account. Recognized secrets are hidden automatically; review the preview before uploading. Reports are used for troubleshooting and may be analyzed with AI assistance. They are retained for **180 days**; to request earlier deletion, contact the author through [support](https://echoink.cn/support) with the report ID. Exporting alone saves a file in your vault without uploading it.

- **Static PRO information:** The plugin’s own interface includes static PRO benefit information and official Skill comparison links opened when you click them. It does not load dynamic online advertising.

- **EchoInk Cloud Sync.** Off by default on desktop and mobile. Enabling it requires sign-in, an activated device, an active sync entitlement, and the account password used to derive an encryption key on the device. https://echoink.cn/sync/ receives your account token, device ID, device display name, device type, opaque path identifiers, sizes, checksums, revisions, and deletion status. The desktop default display name comes from the system device name and can be changed in Cloud Sync settings. In-scope notes, attachments, relative paths, empty folders, and file edit times are encrypted on the device before being sent through the sync service or signed object-storage links. Keys stay on the device. Memory, journal, and financial files saved within the sync scope also sync. Configuration folders, hidden files and folders, and folders you exclude are skipped. Attachment sync can be turned off. Current encrypted files are kept in object storage, with the manifest and device data in the sync service database. Replaced, deleted, or reset objects are reclaimed after about seven days. When a subscription expires, the sync space is read-only for 30 days and is then cleared. Versions kept for conflict recovery are stored locally. See the [website privacy policy](https://echoink.cn/support#privacy) for the production manifest and storage regions and any retention periods unspecified here.

- **Xiaoecho cloud models and AI credits.** After sign-in on desktop, the plugin uses https://echoink.cn/api/xiaoecho/models and https://echoink.cn/api/points to fetch the model catalog, credit balance, and usage records, and adds xiaoecho to the model list. It keeps your existing default when that model can run. Using xiaoecho sends the selected model tier, login token, and the conversation, instructions, note or memory excerpts, material from supported attachments, and tool results needed for inference to https://echoink.cn/api/xiaoecho/chat/completions. EchoInk forwards the inference material through a model gateway to the upstream model in use. A request needs an available service and enough credits from your account balance. Buying Max is a separate membership action. EchoInk's account database stores credits, request status, the model used, usage, and charges. See the [website privacy policy](https://echoink.cn/support#privacy) and the relevant provider's policy for gateway and upstream processing locations, conversation-content retention, and credit log retention.

- **Smart judgment.** The switch is on by default on desktop and mobile. Turn it off under Account & membership. The service requires sign-in, active PRO access, server rollout access, and available judgment quota. Depending on the feature in use, the plugin sends the login token, a request ID, current input and limited recent messages, candidate skills, memory titles and summaries, redacted candidate note excerpts, or fields needed for finance imports and journal or to-do deduplication to https://echoink.cn/api/decisions/. EchoInk sends the material needed for the judgment to Nace Drex, whose default endpoint is https://console.nace.ai. EchoInk's account database records the account, scenario, model, usage, timing, result status, and quota charges. The plugin's request text is excluded from judgment logs. See the [website privacy policy](https://echoink.cn/support#privacy) and Nace's policy for processing regions and log retention periods unspecified here.

- **Desktop News.** When a signed-in user with PRO access opens News in the workbench, the plugin sends the login token and an optional cache identifier to https://echoink.cn/api/news/feed to check access and fetch public news summaries. Availability depends on the server's rollout and pause settings. Notes and profile data are used for relevance ranking on the device and are not uploaded with that request. The last feed is cached in the current vault's plugin data directory. The server keeps the public feed it distributes and information needed for account rate limiting. See the [website privacy policy](https://echoink.cn/support#privacy) for processing regions and log retention periods unspecified here.

- **Problem reports from 2.9.0 onward.** Uploading to https://echoink.cn/api/run-reports requires sign-in. A free account is sufficient. Uploads still require your confirmation, and local export works without sign-in. EchoInk's report storage and database keep the report and account association. Report text and records are retained for 180 days. The website's account service is hosted in Hong Kong. See the [website privacy policy](https://echoink.cn/support#privacy) for the report storage region.

- **Website entry links.** Clicking a support, benefits, pricing, or other website link in the plugin opens https://echoink.cn in the browser. The link can include a fixed entry type, and a checkout link can also include the plan and currency you selected. Entry markers require no sign-in and carry no notes, account IDs, or device IDs. The [website privacy policy](https://echoink.cn/support#privacy) covers website analytics controls, processing, and retention.

- **Check-in credits.** When you submit a check-in to https://echoink.cn/api/check-ins, the server uses your account history to calculate credits. The existing check-in request includes your login token, date, and time zone. Credit grants are linked to your account and stored in the account database. Credits expire after 30 days. See the [website privacy policy](https://echoink.cn/support#privacy) for credit ledger retention.

- **Update checks and release notes.** EchoInk reads public release information from https://echoink.cn/api/releases.

## Data sent to third-party services

- **Model requests:** Your selected model service receives the prompts, notes, attachments, memory, and tool results needed for the current AI request. Model services may require their own account and charge separately; image input requires a vision-capable model.

- **Web search:** Web search is off by default, with a choice of Tavily or DeepSeek. When enabled, queries go to the selected service at `api.tavily.com` or `api.deepseek.com`, and returned snippets and links go to your model. Each service uses its own account and API key and bills usage separately; connection tests also perform a real search. Tavily connection tests use basic search and consume one credit; see [Tavily's pricing policy](https://docs.tavily.com/documentation/api-credits). DeepSeek query limits and billing are described in its [search documentation](https://api-docs.deepseek.com/guides/search/).

- **PDF parsing:** Local PDF text extraction runs on your device. MinerU enhanced parsing sends the PDF to MinerU, requires separate credentials and credits, and follows that service's retention policy. Extracted content needed for reading notes or translations is sent to your selected model.

- **Link capture:** Link capture uses the plugin's built-in fetcher to access pages you explicitly submit.

- **Custom services and MCP:** Custom Providers and MCP connections contact the services or local commands you configure. Local MCP processes run with your operating-system user permissions and inherit the application environment; approving tools in the plugin does not restrict those processes to the workspace.

- **AI actions in note comments.** The desktop comment toolbar is enabled by default. Creating a comment requires sign-in and active PRO access on the device. Comments are stored in the current vault's plugin data directory. Writing a regular comment makes no model request. When you choose to explain, translate, find related notes, or ask an agent in a thread, the selected model service receives the material needed for that action. This may include selected text, surrounding passages, the comment thread and question, or candidate note titles, paths, and excerpts. The selected model service determines its address, credentials, billing, and retention. The cloud model disclosure above applies when you use xiaoecho.

- **Custom RSS and news sources.** The subscription list is empty by default. Desktop News subscription settings require sign-in and PRO access. Adding a feed or opening News with feeds configured makes a request from your device to the RSS or Atom URL you supplied. That site receives the feed URL and no EchoInk login token, notes, or profile data. The subscription list stays in plugin settings and fetched items are cached in memory. Clicking the original opens the publisher's site in the browser. Its policy governs its network logs and retention. If you ask an agent to explain an article, relevant material goes to the selected model.

## Local permissions and external agents

- **Desktop workspace:** Desktop conversations can use a local workspace outside the vault. File access follows the selected permission mode; Full access removes the workspace boundary. Outside-vault attachments are read when you explicitly select, drag, or paste them.

- **EchoInk MCP server:** EchoInk’s desktop MCP server is PRO, off by default, read-only, and listens only on this computer’s loopback address while Obsidian is running. You separately authorize Knowledge and personal memory/profile access. External Agents can receive note excerpts, source paths and revisions, concept links, your profile and memories, and may send them to their model providers or retain them. EchoInk cannot control those records or recall content already sent. Turn off sharing or regenerate the token to stop future access.

- **MCP task context:** An external agent calling `get_context` sends the task and optional recent conversation. When smart judgment is enabled and available, the task, recent context, memory summaries, and authorized note excerpts needed for selection may be processed under the smart judgment terms above. Selected results stay in local memory for up to 10 minutes. Turning smart judgment off stops reuse of cached selections. When it is off or the allowance runs out, the tool returns authorized candidates. Results from a timed-out note search are not cached.

- **Knowledge retrieval scope:** Knowledge retrieval excludes the private-memory and internal plugin data folders. This is not a global access restriction for every file tool or third-party service.

- **Folder access when dispatching work.** The assistant can grant assigned agents access to regular folders by default. You can turn this off in the desktop assistant editor. Project folders can also be opened to project staff. Agents can read ordinary notes for their tasks. Writes remain subject to module ownership and the applicable permissions. This rule makes no network request. Any content an agent reads and sends to a model follows that provider's policy.

## Website and account service

- EchoInk does not collect client-side telemetry. See above for data handling for website sign-in, hire counts, and other network requests.

See the website [privacy policy](https://echoink.cn/support#privacy) for website and account-service data handling.
